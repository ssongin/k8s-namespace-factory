# Repository Maintainers

Maintainers own the Ansible playbook, variable schema, GitHub Actions
workflows, and documentation site.

## Pull request and release checks

The workflows in `.github/workflows/` call the reusable workflows from
`gha-commit`, `gha-ansible`, and `gha-docs`:

- Pull requests validate the Conventional Commit message, lint and syntax
  check Ansible, validate `host_vars/`, and publish a documentation preview
  for same-repository pull requests.
- Pushes to `master` run the same checks. Once they pass, the workflows update
  the latest docs, create a semantic version tag when the commit message
  calls for one, and publish tagged docs when a tag was created.

The current Ansible checks do not connect to a Kubernetes cluster. No
`kubeconfig` or provider credentials are required by these checks. GitHub
Pages publishing requires Pages to be configured for this repository and the
workflow permissions declared in the workflow files.

Commit headers must follow the supported Conventional Commit format, such as
`feat(namespace): support a new option` or `fix: correct validation`. See
[`gha-commit` validation guidance](https://ssongin.github.io/gha-commit/validation)
and [versioning](../versioning.md) for accepted types and release behavior.

## Maintain the host-variable schema

Update `schemas/namespace-schema.json` when the shape of the variables consumed
by `apply.yml` changes. Keep the schema aligned with the role inputs and
`host_vars/sample.yaml`. The `gha-ansible` workflow checks all YAML files in
`host_vars/` against it on pull requests and pushes to `master`.

When adding an Ansible dependency, update `requirements.yml`. The CI workflow
installs that Galaxy requirements file before checking `apply.yml`.

The `.ansible-lint` configuration skips the role-name and variable-name
conventions because existing role paths and host-variable keys are consumed
throughout the project. Keep those names consistent when adding or changing
configuration.

## Build the documentation locally

Requirements: Node.js 22 and npm.

```sh
npm ci --prefix docs
npm run docs:dev --prefix docs
```

Build the static site before merging documentation changes:

```sh
npm run docs:build --prefix docs
```

The version selector is implemented in
`docs/.vitepress/theme/VersionSelector.vue` and reads the version manifest
generated by `gha-docs` from the published Pages site.
